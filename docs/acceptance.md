# 6장 과제 기준별 구현·검증 기록

검토 자료: 사용자가 첨부한 과제 개요 1장과 카드 1~5 안내, 총 6장. 아래는 구현과 실행 근거를 구분한 기록이며 미실시한 원격 작업을 통과로 표시하지 않는다.

## 이번 보완

1. 실제−예상 차이와 빈 자료의 0 처리, 계획별 집계 및 동일 판정 시각을 추가했다.
2. `task_completions.task_id` 기본키와 트랜잭션으로 중복 완료 이력·집계를 막았다. 완료 이력은 실행 시간 기록과 구분한다.
3. 돌아보기 문장을 다음 계획 양식으로 넘기고 `reflection_links`로 두 계획과 당시 문장을 보존한다.
4. 모든 집계 숫자에서 근거 목록을 거쳐 할 일·실행 기록·계획 원본으로 이동한다. 검색에 가려진 할 일은 필터를 해제하고 보여 준다.
5. 정렬 동률 규칙·단위·시간대·집계 기준을 화면과 README에 표시했다.
6. `contracts/pds-schema.v2.json`에 최종 자료 구조·관계·날짜·단위·집계·이력 정책을 작성하고 실제 내보내기 응답을 JSON Schema로 검증한다. 제공 이미지에 없는 공식 원본 명세를 임의로 복원했다고 주장하지 않는다.
7. 일반 배포와 단일 파일 배포 모두 정적 파일 보안 헤더를 적용한다. 원문 저장 오류가 서버 로그에 출력되지 않도록 바꿨다.

## 자동 검증 환경과 결과

- Node.js의 `node:sqlite` 메모리 DB로 D1의 prepare/bind/run/all/first와 원자적 batch를 모사한다.
- jsdom에서 실제 `public/index.html`과 `public/app.js`를 실행하고 같은 Worker API에 연결한다. 실제 원격 D1·브라우저 배포 검증을 대체한다고 주장하지 않는다.
- `npm test`: API·집계·스키마·화면 동작 테스트 12개 통과.
- `npm run build`: 단일 모듈 `dist/worker.js` 생성 성공.
- 사용자의 Windows 설치 출력에서 발견된 Ajv 경고를 확인하고 테스트 의존성을 8.20.0으로 수정했다. npm 11.19.1에서 설치 스크립트 승인 설정을 만들었으며 필요한 esbuild·workerd의 현재 버전에만 적용한다.
- 위 의존성 수정 후 npm 11.19.1 재설치·테스트 12개·빌드·Wrangler 배포 dry-run을 확인했다. `npm audit` 결과는 발견된 취약점 0건이다. dry-run은 실제 공개 앱 배포 완료를 뜻하지 않는다.
- 자동 검증용 계획·할 일·시각은 테스트 자료이고 사용자의 실제 활동 기록이 아니다. 공개 D1에 자동으로 넣지 않는다.

## 안내 이미지와 최종 대조

2026-10-23에 안내 이미지 6장을 다시 읽고, 카드 5가 지정한 명세 경로를 `contracts/pds-schema.v2.json`으로 맞췄다. 이전 하이픈 파일명은 제거하고 README·검수 문서·테스트의 참조와 명세의 `$id`도 수정했다. 내보내기의 `schema_version` 값과 앱 동작은 변경하지 않았다. 이 경로 수정은 실행 앱에 포함되는 코드 변경이 아니므로 재배포가 필요 없다.
