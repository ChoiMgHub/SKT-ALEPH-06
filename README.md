# 플랜드씨 다이어리 — 6장 과제

계획(Plan) → 실제 실행(Do) → 근거를 보며 돌아보기(See)를 한 화면에서 이어 쓰는 공개 다이어리입니다. 예시로 **“6장 과제 완성하기”**라는 실제 계획을 등록했습니다.

## 결과물

- 앱: https://skt-aleph-06.mingi85308530.workers.dev/
- 소스: https://github.com/ChoiMgHub/SKT-ALEPH-06
- 저장: Cloudflare D1 데이터베이스 `aleph-diary`

## 확인 방법 — 4줄

1. 앱 주소를 열면 로그인 없이 계획·할 일·실행 기록·돌아보기가 보입니다.
2. `계획`에서 값을 바꿔 저장하고, `할 일`을 완료한 뒤, `실제`에서 시작·종료 시각을 저장합니다.
3. `돌아보기` 숫자를 눌러 근거 기록을 확인하고, `전체 자료 파일로 받기`로 JSON을 내려받으면 성공입니다.
4. 저장 뒤 새로고침해도 내용이 남아야 합니다. 저장 오류가 나오면 입력값과 네트워크를 확인하고 다시 시도합니다.

## 들어 있는 기능

- 계획의 기간·우선순위·성공 기준·예상 시간 저장, 수정 직전 값 이력 보존
- 할 일 추가·수정·완료 전환·삭제, 마감·우선순위·분류·상태, 검색·거르기·정렬
- 실행 기록의 시작·종료·실제 시간·계획과 달랐던 이유 저장; 같은 요청의 중복 저장 방지
- 서버 데이터로 완료·지연·막힘·예상 시간·실제 시간 계산, 숫자를 누르면 근거 기록 표시
- 다음 계획에 넘길 한 줄과 전체 데이터 JSON 내보내기

## AI 활용 — 3줄

1. AI에 맡긴 일: 요구사항 분석, 주제 선정, 화면·서버·데이터베이스 설계와 구현, 배포 및 검증.
2. 직접 판단한 일: Cloudflare 계정을 만들고 로그인했으며, 간단한 주제 선정과 기술 작업을 AI에 맡기기로 결정.
3. AI 제안을 그대로 따르지 않은 일: 없음. 간단한 주제와 구현을 AI에 맡기기로 한 판단에 따라 제안된 결과를 실제 앱에서 검증함.

## 저장·보안 안내

서버의 D1 데이터베이스에 저장되므로 새로고침 뒤에도 유지됩니다. 현재 로그인 기능이 없어 **링크를 아는 사람은 내용을 읽고 수정할 수 있습니다.** 민감한 정보는 적지 마세요. 화면은 사용자 입력을 텍스트로 출력하고, 정적 파일에는 콘텐츠 보안 정책을 적용했습니다. 비밀번호·API 키·토큰은 소스에 넣지 않았습니다.

## 개발·검증

Node.js 환경에서 `npm install` 후 `npm test`로 API 검증을 실행할 수 있습니다. `npm run dev`는 로컬 실행, `npm run deploy`는 Cloudflare 배포입니다. 원격 D1 스키마는 `schema.sql`에 있고, `wrangler.jsonc`의 `DB` 바인딩을 사용합니다. `npm run build`는 Cloudflare 대시보드에 직접 올릴 수 있는 단일 모듈 `dist/worker.js`를 만듭니다.

검증 항목: 계획 수정 전 값 보존, 실행 기록 중복 방지, 완료한 일의 지연 제외, 예상값과 실제값 분리, JSON 내보내기, 스크립트처럼 생긴 입력의 텍스트 보존, 공개 주소에서 서버 저장·새로고침 확인.
